# Comparative Analysis and Experimental Evaluation of Task-Based Parallel Programming Systems

This repository contains the full LaTeX source code and the experimental testbed for the diploma thesis on the comparative analysis and experimental evaluation of task-based parallel programming systems.

As Python dominates scientific computing, the efficient utilization of modern hardware (such as complex NUMA architectures) is often hindered by inherent interpreter limitations, most notably the Global Interpreter Lock (GIL). This project addresses these challenges by investigating two platforms with fundamentally different design philosophies to evaluate their performance, overhead, and scalability on modern multicore systems.

## Frameworks Compared

1. **StarPUPy**: A Python interface for StarPU, primarily built for shared memory and heterogeneous systems.
2. **torcpy**: A Python-native system built upon the distributed MPI standard.

## Applications Evaluated

The evaluation was conducted using three representative scientific applications:
- **app00 (CMA-ES)**: Stochastic optimization coupled with a PDE solver.
- **app01 (Gabor Filter)**: Image texture analysis and heavy image processing pipeline.
- **app02 (Monte Carlo)**: A Monte Carlo simulation for financial derivative pricing.

Additionally, several smaller examples (`ex00` to `ex06`) are included to isolate and measure specific framework overheads, task scheduling efficiency, and specific programming primitives (e.g., map, submit/wait).

## Repository Structure

- `Thesis/`: Contains the complete LaTeX source code for the diploma thesis document. The compiled document provides in-depth theoretical background, methodology, and detailed analysis. 
- `MyExamples/`: The experimental framework used for performance evaluation.
  - `starpupy_examples/`: Source code and benchmark applications implemented using StarPUPy.
  - `torcpy_examples/`: Source code and benchmark applications implemented using torcpy.
  - `test_scripts/`: Bash scripts for automating benchmark execution across different configurations.
  - `test_results/`: Logs and CSV output generated by the test scripts.
  - `images/`: Sample dataset images used in the Gabor filter application.
  - `results_comparison.md`: A concise markdown summary of the experimental timing results.

## Key Findings

The experiments evaluated both fine-grained overhead and heavy computational workloads. Some key takeaways from the execution on a 64-core system include:
- **Fine-Grained Workloads:** **StarPUPy** generally performs better on overhead-dominated tasks (e.g., map, submit/wait) due to its shared-memory design and lower task submission latency.
- **Heavy CPU Workloads:** **torcpy** excels in process-level scaling (such as CMA-ES) thanks to its multi-process MPI-based architecture, effectively bypassing Python's GIL.
- **Overall Throughput:** Both systems demonstrated comparable behavior in specific scenarios (e.g., the Monte Carlo simulation).
- **NUMA Effects:** NUMA-aware execution showed only marginal improvements in the specific tested scenarios.

For full timing measurements and exact testing configurations, please check `MyExamples/results_comparison.md` or compile the main LaTeX document in `Thesis/main.tex`.
