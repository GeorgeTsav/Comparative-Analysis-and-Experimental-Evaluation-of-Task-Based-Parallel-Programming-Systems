\chapter{Το Σύστημα StarPU} 

\section{Τι είναι το StarPU}

Όπως έχουμε ήδη αναφερεί πολλές φορές είναι ότι τα συστήματα που χρησιμοποιούνται για εφαρμογές \textbf{HPC}, είναι πολύ περίπλοκα. Γι' αυτό το λόγο άλλωσστε έχουμε αρχιτεκτονικές \textbf{NUMA}, που εισάγουν την έννοια της ετερογένειας \textbf{(heterogeneity)} στην πρόσβαση στη μνήμη αλλά και στην φύση της επεξεργαστικής μονάδας \textbf{(Processing Unit - PU)}. Δηλαδή ένα σύστημα NUMA μπορεί να έχει επεξεργαστικές μονάδες που είναι πέρα από \textbf{CPUs}, αλλά και \textbf{GPUs} ή \textbf{FPGAs} κ.α. Η ετερογένεια αυτή κάνει την ανάπτυξη εφαρμογών για τέτοια συστήματα πολύ δύσκολη, καθώς ο προγραμματιστής πρέπει να λάβει υπόψη του τις ιδιαιτερότητες και την υποκείμενη αρχιτεκτονική κάθε τύπου επεξεργαστικής μονάδας και να διαχειριστεί την κατανομή των εργασιών και των δεδομένων με τρόπο που να μεγιστοποιεί την απόδοση.

Την λύση σε αυτό το πρόβλημα έρχεται να δώσει το \textbf{StarPU}, ένα runtime system που παρέχει ένα ενοποιημένο περιβάλλον για την ανάπτυξη εφαρμογών σε ετερογενή συστήματα. Το StarPU επιτρέπει στους προγραμματιστές να γράφουν κώδικα που μπορεί να εκτελεστεί σε διάφορους τύπους επεξεργαστικών μονάδων χωρίς να χρειάζεται να ανησυχούν για τις λεπτομέρειες της αρχιτεκτονικής κάθε μονάδας. Παρέχει μηχανισμούς για την κατανομή των εργασιών, τη διαχείριση της μνήμης και την επικοινωνία μεταξύ των επεξεργαστικών μονάδων, επιτρέποντας έτσι την αποτελεσματική εκμετάλλευση των πόρων του συστήματος \cite{augonnet2009starpu, starpu2025handbook}.

Η θεμελιώδης αρχή λειτουργίας του StarPU είναι να «κάνει δυναμικά ό,τι δεν μπορεί πλέον να γίνει στατικά», καθιστώντας τις εφαρμογές φορητές και ιδιαίτερα κλιμακώσιμες χωρίς να θυσιάζεται η απόδοση χαμηλού επιπέδου \cite{augonnet2010starpu_gtc}. Προσφέροντας ένα πλούσιο API σε C, C++ και Fortran, καθώς και υποστήριξη pragma OpenMP, το σύστημα εκτέλεσης απαλλάσσει τον προγραμματιστή από την αντιμετώπιση των λεπτομερειών υλικού χαμηλού επιπέδου, επιτρέποντάς του να επικεντρωθεί αποκλειστικά στην αλγοριθμική λογική \cite{starpu2025handbook}.

Η παρούσα ανάλυση παρέχει μια ολοκληρωμένη και εξαντλητική παρουσίαση του τι επιτυγχάνει το StarPU και των περίπλοκων εσωτερικών μηχανισμών που χρησιμοποιεί για να το πετύχει. Η αξιολόγηση αναλύει τις βασικές αρχιτεκτονικές οντότητες, το υποσύστημα Εικονικής Κοινής Μνήμης \textbf{(Virtual Shared Memory - VSM)}, αλγορίθμους χρονοπρογραμματισμού εργασιών βασισμένους σε μοντέλα απόδοσης πραγματικού χρόνου, τον κύκλο εκτέλεσης των εσωτερικών εργατών του συστήματος εκτέλεσης και την επέκταση αυτών των παραδειγμάτων σε περιβάλλοντα συστάδων κατανεμημένης μνήμης μέσω \textbf{MPI} \cite{augonnet:inria-00467677, augonnet2010data}. 

\section{Η Αρχιτεκτονική του StarPU}

Η αρχιτεκτονική του StarPU αποτελείται από διάφορα βασικά στοιχεία που συνεργάζονται για να παρέχουν το περιβάλλον εκτέλεσης για ετερογενείς εφαρμογές. Οι τρεις κύριες κατηγορίες οντοτήτων είναι οι εξής: Οντότητες Εργασίας, Οντότητες Εκτέλεσης και Οντότητες Δεδομένων. Αυτός ο τριμερής διαχωρισμός επιτρέπει στο σύστημα χρόνου εκτέλεσης να αποσυνδέσει τον αλγοριθμικό ορισμό ενός προβλήματος από τη φυσική εκτέλεσή του στο υλικό \cite{starpu_dev_manual}.

\subsection{Οντότητες Εργασίας}

Στην καρδιά του προγραμματιστικού μοντέλου του StarPU βρίσκονται τα \textbf{Codelets} (struct starpu\_codelet). Ένα codelet ενσωματώνει έναν υπολογιστικό αλγόριθμο (ή πυρήνα υπολογισμού) και παρέχει πολλαπλές υλοποιήσεις για τις διάφορες διαθέσιμες επεξεργαστικές μονάδες \textbf{(PUs)} με βάση την υποκείμενη αρχιτεκτονική. Για παράδειγμα, ένα codelet σχεδιασμένο για την κλιμάκωση ενός διανύσματος μπορέι να περιέχει έναν απλό δείκτη συνάρτησης στην C για την εκτέλεση σε CPU, μια υλοποίηση CUDA για GPU και μια υλοποίηση OpenCL για συσκευές AMD. Η δομή του codelet επισημαίνει ποιο υλικό (hardware) υποστηρίζει μέσω μιας μάσκας bit (π.χ. STARPU\_CPU | STARPU\_CUDA) και υποδεικνύει τον αριθμό των buffer δεδομένων που χειρίζεται (nbuffers). Ενοποιώντας τις διάφορες υλοποιήσεις σε ένα ενιαίο codelet, το StarPU επιτρέπει στο σύστημα εκτέλεσης να επιλέξει δυναμικά την καταλληλότερη υλοποίηση με βάση τη διαθεσιμότητα των πόρων και την τοπικότητα των δεδομένων \cite{starpu2025handbook, starpu_dev_manual, starpu_website}.

Η δεύτερη οντότητα εργασίας είναι τα \textbf{Tasks}. Ένα task είναι μια συγκεκριμένη εμφάνιση ενός codelet που έχει δεσμευτεί με ένα συγκεκριμένο σύνολο δεδομένων. Ένα task λειτουργεί ως μεσολαβητής μεταξύ του συστήματος χρόνου εκτέλεσης (runtime system) και της εφαρμογής. Κατά την υποβολή ενός task μέσω των βοηθητικών συναρτήσεων starpu\_task\_submit ή starpu\_task\_insert, ο προγραμματιστής καθορίζει το codelet, τα δεδομένα πάνω στα οποία θα εκτελεστεί (μέσω \textbf{Data Handles}) και τους τρόπους πρόσβασης (π.χ. STARPU\_R, STARPU\_W, STARPU\_RW). Επιπλέον, η δομή του task υποστηρίζει προαιρετικά πεδία που παρέχουν υποδείξεις προς τον χρονοπρογραμματιστή, όπως επίπεδα προτεραιότητας, χρώμα εκτέλεσης για προφίλ και συναρτήσεις επανάκλησης (callback\_func) που ενεργοποιούνται μετά την επιτυχή ολοκλήρωση του task. Τα Tasks είναι εκ φύσεως ασύγχρονα από προεπιλογή, ωστόσο οι προγραμματιστές μπορούν να επιβάλουν σύγχρονη εκτέλεση ορίζοντας task->synchronous = 1 \cite{starpu2025handbook, starpu_dev_manual, starpu_website}.

Η τελευταία οντότητα εργασίας είναι τα \textbf{Jobs}. Ένα job είναι μια δομή που χρησιμοποιεί εσωτερικά το StarPU για να αναπαραστήσει ένα task. Είναι μια χαμηλού επιπέδου οντότητα που διασχίζει τον εσωτερικό γράφο χρονοπρογραμματισμού. Ο διαχωρισμός μεταξύ tasks και jobs δίνει τη δυνατότητα για εξελιγμένες λειτουργίες όπως η παράλληλη εκτέλεση εργασιών, όπου μια μόνη δομή job μπορεί να συντονίσει πολλαπλές δομές παράλληλων tasks αντιστοιχισμένες σε μια ομάδα εργατών που χρησιμοποιούν παραλληλοποίηση σε επίπεδο νημάτων (όπως OpenMP). Η δομή job περιέχει εσωτερικά μεταδεδομένα που απαιτούνται για την ανάλυση εξαρτήσεων, την ουρά προτεραιοτήτων και την παρακολούθηση μοντέλων απόδοσης \cite{starpu2025handbook, starpu_dev_manual, starpu_website}. 

\subsection{Οντότητες Εκτέλεσης}

Η κεντρική οντότητα εκτέλεσης στο StarPU είναι ο \textbf{Worker}. Ένας worker είναι πάντα ένα νήμα (thread) CPU που έχει ως μοναδική ευθύνη την διαχείρηση μιας συγκεκριμένης μονάδας υπολογισμού (PU). Για παράδειγμα, σε ένα σύστημα με 4 CPU και 2 GPU, το StarPU θα δημιουργήσει 6 workers: 4 για τους CPUs και 2 για τις GPUs. Ένας worker αν σχετίζεται με μια CPU είναι υπεύθυνος για την εκτέλεση των tasks. Αλλίως στην περίπτωση που σχετίζεται με μια GPU ή άλλου είδους PU, τότε δρα σαν διαχειρηστής για την συγκεκριμένη PU και δεν εκτελεί τον υπολογισμό. Δηλαδή, συνέχεια ρωτά για νέα tasks, μεταφερεί δεδομένα μέσω της διαύλου (bus) και στέλνει εντολές προς εκτέλεση στην PU που διαχειρίζετε. Αυτή ησχεδιατική επιλογή είναι πολύ σημαντική, διότι επιτρέπει στο StarPU να διασφαλίζει ότι η δίαυλος και οι ουρές εντολών της συσκευής είναι μόνιμα κορεσμένα, αποκρύπτοντας αποτελεσματικά την καθυστέρηση υλικού \cite{starpu_dev_manual, starpu2025handbook, augonnet2010data}. 

Η επόμενη οντότητα εκτέλεσης είναι οι \textbf{Drivers}. Οι drivers είναι οι διαμεσολαβητές μεταξύ των workers και του υλικού. Δίνουν στους worker ένα API ώστε να μπορούν να αρχικοποιούν το εκάστοτε υλικό, να χαρτογραφούν την μνήμη, να στέλνουν τα tasks στο εκάστοτε PU και να καθαρίζουν τα αχρίαστα δεδομένα μετά την εκτέλεση. Οι StarPU υποστηρίζει drivers για διάφορα είδη υλικού: CPU, CUDA, OpenCL, HIP, ακόμη και MPI Master-Slave διατάξης \cite{starpu2025handbook, starpu_dev_manual}.

Η τελευταία οντότητα εκτέλεσης είναι τα \textbf{Scheduling Contexts}. Για να μπορεί να γίνει διαχέιρηση των σύνθετων τοπολογιών υλικού, οι workers οργανώνονται σε scheduling contexts. Ένα scheduling context δεσμεύει μία ομάδα από workers σε ένα συγκεκριμένο αλγόριθμο χρονοπρογραμματισμού (scheduling algorithm). Για παράδειγμα, σε ένα σύστημα με 4 CPU και 2 GPU, το StarPU επιτρέπει στον προγραμματιστεί να δημιουργήσει δύο scheduling contexts: ένα για τους 4 workers των CPU που χρησιμοποιούν έναν αλγόριθμο χρονοπρογραμματισμού βασισμένο σε προτεραιότητα (priority-based scheduling) και ένα άλλο για τους 2 workers των GPU που χρησιμοποιούν έναν αλγόριθμο χρονοπρογραμματισμού βασισμένο σε απόδοση (performance-based scheduling). Αυτή η οργάνωση επιτρέπει στο StarPU να προσαρμόζει την στρατηγική χρονοπρογραμματισμού ανάλογα με τα χαρακτηριστικά του υλικού και τις απαιτήσεις της εφαρμογής \cite{starpu2025handbook, starpu_dev_manual}. 

\subsection{Οντότητες Δεδομένων}

Η βασική οντότητα δεδομένων στο StarPU είναι το \textbf{Data Handle}. Ένα data handle είναι μια αδιαφανής αναφορά υψηλού επιπέδου σε ένα κομμάτι των δεδομένων της εφαρμογής. Λειτουργεί ως ''λογική ταυτότητα'' για τα δεδομένα, επιτρέποντας έτσι στο StarPU να παρακολουθεί να τα αιτήματα πρόσβασης (ανάγνωση, εγγραφή, ανάγνωση-εγγραφή) που κάνουν τα tasks. Έτσι το StarPU είναι σε θέση να αναλύει τις εξαρτήσεις μεταξυ των tasks και να φτιάχνει αυτόματα το γράφημα εξερτήσεων \textbf{(DAG)} \cite{starpu2025handbook,starpu_dev_manual}.

Η δεύτερη οντότητα δεδομένων είναι το \textbf{Data Replicate}. Ένα data replicate είναι μια οντότητα χαμηλού επιπέδου που αντιπροσωπεύει ένα συγκεκριμένο φυσικό αντίγραφο των δεδομένων ενός data handle, το οποίο βρίσκεται αποθηκευμένο σε έναν συγκεκριμένο κόμβο μνήμης που τον διαχειρίζεται το StarPU. Για σε έναν σύγχρονο σύστημα HPC, κόμβοι μνήμης είναι η κύρια μνήμη RAM της CPU, η ενσωματωμένη μνήμη VRAM της GPU 0, η VRAM της GPU 1, ή ακόμα και ο σκληρός δίσκος. Ένα Data Replicate είναι η πραγματική, φυσική αποτύπωση των δεδομένων της εφαρμογής σε έναν από αυτούς τους χώρους. Τέλος, ένα data replicate δεν είναι εμφανές στην εφαρμογή αλλά είναι χρήσιμη μόνο για το StarPU όπως θα δούμε στην συνέχεια \cite{starpu2025handbook, starpu_dev_manual}.

\section{Υποσύστημα Εικονικής Κοινής Μνήμης (VSM)}

Σε ετερογενή συστήματα HPC, ο κύριος παράγοντας που περιορίζει την απόδοση είναι οι μεταφορές δεδομένων. Για να αξιοποιηθεί πλήρως το υλικό, ένα σύστημα χρόνου εκτέλεσης πρέπει να ελαχιστοποιήσει αυτές τις μεταφορές και να τις επικαλύψει με τους υπολογισμούς. Το StarPU το επιτυγχάνει εφαρμόζοντας την αφαίρεση της Εικονικής Κοινής Μνήμης \textbf{(Virtual Shared Memory - VSM)}.

\subsection{Δομές και Διεπαφές Δεδομένων}

Όπως αναφέραμε και στην υποενότητα 3.2.3, το StarPU χρησιμοποιεί δύο βασικές οντότητες δεδομένων: τα \textbf{Data Handles} και τα \textbf{Data Replicates}. Ένα data handle επιστρέφεται όταν ο προγραμματιστής εγγράφει ένα κομμάτι δεδομένων στο σύστημα χρόνου εκτέλεσης, έναντι του κλασικού τρόπου με pointers C. Η φυσική διάταξη και το αποτύπωμα μνήμης των δεδομένων περιγράφονται από μια διεπαφή δεδομένων \textbf{(Data Interface)}. Το StarPU παρέχει αρκετές προκαθορισμένες διεπαφές δεδομένων για διάφορες δομές δεδομένων που συναντιόνται συχνά σε επιστημονικούς υπολογισμούς, όπως \cite{starpu2025handbook, starpu_dev_manual}:

\begin{itemize}
  \item \textbf{Variable/Scalar Interface}: Για μεμονωμένες αριθμητικές τιμές ή μικρές δομές σταθερού μεγέθους (starpu\_variable\_data\_register).
  \item \textbf{Vector Interface}: Για μονοδιάστατους πίνακες με συνεχόμενα στοιχεία (starpu\_vect\\or\_data\_register).
  \item \textbf{Matrix \& Block Interfaces}: Για δισδιάστατες και τρισδιάστατες πυκνές δομές δεδομένων, λαμβάνοντας υπόψη τις κύριες διαστάσεις (LD) για εξαγωγή υπο-πινάκων χωρίς περιορισμούς συνεχόμενης μνήμης (starpu\_matrix\_data\_register).
  \item \textbf{Sparse Interfaces}: Ενσωματωμένη υποστήριξη για μορφές Compressed Sparse Row (CSR), Block Compressed Sparse Row (BCSR) και Coordinate (COO), ενεργοποιώντας σύνθετους επιλύτες αραιής γραμμικής άλγεβρας.
  \item \textbf{N-Dimensional Tensor Interface}: Για εργασίες βαθιάς μάθησης και πολυδιάστατους πίνακες.
\end{itemize}

Με την αφαίρεση των δεδομένων σε data handles, το StarPU μπορεί να παρεμβαίνει σε κάθε αίτημα πρόσβασης σε αυτά. Ένα data handle δεν αντιπροσωπεύει ένα μεμονωμένο φυσικό buffer, αλλά λειτουργεί ως ένα γενικό μηχάνημα κατάστασης που παρακολουθεί πολλαπλά data replicates. Πάνω σε αυτό βασίζεται ο μηχανισμός συνοχής MSI (Modified, Shared, Invalid) που θα αναλύσουμε στην επόμενη υποενότητα \cite{starpu2025handbook, starpu_dev_manual}.

\subsection{Πρωτόκολλο Συνοχής MSI (Modified, Shared, Invalid)}
